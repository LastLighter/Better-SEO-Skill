# 01 · 核心原则与快速上手

## 1. 触发场景

在以下任一情形中启用本 Skill：

- 生成前端组件（页面 Header、卡片、按钮、表单、Footer）
- 设计页面结构（信息架构、路由规划、区块划分）
- 撰写落地页 / 灵感广场内容
- 配置 Meta 标签、结构化数据
- 优化用户交互工作流（提示词标签、参数预设、一键同款）

## 2. 三大核心原则

### 意图契合（Search Intent）

> 长尾词不硬塞，必须转化为用户刚需的功能模块或内容载体。

- 拿到一个长尾词，先问：**用户搜这个词时想完成什么动作？** 然后把这个动作做成一个按钮、一个预设、一个页面。
- 一个长尾词只能对应一个「载体」。找不到载体，就说明该词不该上页面。
- 反面案例：把 50 个长尾词堆进 Meta keywords（现代搜索引擎已忽略）或 Footer 无意义锚文本。

### 体验优先（UX First）

> SEO 元素必须提升用户的交互效率。

- 标准：这个 SEO 改动，能不能用「用户会因此更快完成任务」解释？不能，就不做。
- 正面案例：预设标签可点击直接生图 —— 既覆盖了「二次元 AI 生图」这个词，又让用户少打 20 个字。
- 正面案例：教程里的 Prompt 旁有「一键复制并生成」，而不是让用户手动选中复制。

### 机器可读（Crawler Friendly）

> 确保关键信息（H1–H3、Alt、Schema.org）能够被搜索引擎爬虫无障碍读取。

- 关键信息必须存在于 **服务端渲染的 HTML 文本节点**里。
- 不要把文字画在 Canvas、图片、CSS 背景图或 tooltip 中。
- 语义标签（`h1`–`h3`、`img alt`、`a href`、`nav`）是给爬虫和辅助技术看的路标。

## 3. 三原则冲突时的优先级

```
机器可读 > 体验优先 > 意图契合
```

理由：机器不可读意味着内容根本进不了索引，再好的体验也没有流量；
而只要体验和意图冲突时，优先保住用户完成任务的路径（体验），
再通过额外内容载体去补长尾覆盖。

> 例外：当「机器可读」的实现会破坏核心交互（如在输入框里塞入不可编辑的关键词堆砌文本），
> 则改为在页面其他位置提供等价的文本节点，而不是牺牲交互。

## 4. 决策流程（30 秒版）

```
拿到需求
 ├─ 这是什么页面类型？(首页/工具/列表/详情/落地页/教程)
 ├─ 目标长尾词是什么？它能映射到哪个功能或内容载体？
 ├─ 元数据四件套写了吗？(Title / Description / H1 树 / JSON-LD)
 ├─ 用了 4 大模式中的哪一个？该词在 UI 上落在哪个组件？
 ├─ 图片/语义化/Footer 矩阵过 Hard Rules 了吗？
 └─ 6 项 CheckList 全绿了吗？（跑 scripts/seo_audit.py）
```

## 5. 术语表

| 术语 | 含义 |
| --- | --- |
| 长尾词 | 搜索量较低但意图明确的具体词组，如「免费 AI 贴图生成」 |
| 语义集群 | 围绕同一主题互相内链的一组页面（列表 + 详情 + 落地页 + 教程） |
| 程序化落地页 | 用模板 + 数据批量生成的定向入口页，如 `/s/{keyword-slug}` |
| Doorway page | 只换关键词、内容雷同的批量页，属违规做法 |
| Rich Snippet | 搜索结果中的富文本展现，由结构化数据驱动，如评分星级 |
| CLS / LCP / INP | Core Web Vitals 三项体验指标 |
| slug | URL 中的语义化短标识，如 `anime-ai-generator` |
